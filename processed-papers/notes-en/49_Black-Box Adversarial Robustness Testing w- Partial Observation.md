# 49. Black-box Adversarial Robustness Testing with Partial Observation for Multi-Agent Reinforcement Learning

## Metadata
- **Title**: Black-box Adversarial Robustness Testing with Partial Observation for Multi-Agent Reinforcement Learning
- **Authors**: Bang Zhang, Wenjian Luo (corresponding), Kesheng Chen, Yujiang Liu, Shuhan Qi, Xuan Wang
- **Affiliation**: Guangdong Provincial Key Laboratory of Novel Security Intelligence Technologies, Institute of Cyberspace Security, School of Computer Science and Technology, Harbin Institute of Technology, Shenzhen, Guangdong, China
- **Venue**: IEEE ICPADS 2025 (31st International Conference on Parallel and Distributed Systems)
- **Link/arXiv**: DOI: 10.1109/ICPADS67057.2025.11323102

## Taxonomy
- **Robustness / perturbation type targeted**: State/observation perturbation via adversarial attacks on agents' observations in cooperative MARL; black-box, sparse (low perturbation-step) attacks under strict partial-observation constraints
- **Method paradigm**: Adversarial attack / robustness testing (black-box); victim-agent and attack-time selection via Q-value difference (ΔQ); FGSM-style perturbation generation with zeroth-order gradient estimation (query-based) and substitute-model transferability attacks
- **Keywords**: multi-agent reinforcement learning, black-box attack, adversarial attack, robustness testing, partial observation

## TL;DR
The paper proposes a two-step black-box robustness-testing framework for cooperative MARL that, under strict partial-observation constraints, first selects a single victim agent and the attack timing from one ally's or one enemy's observation (AOA / EOA) using the Q-value difference ΔQ, then adds FGSM-style adversarial perturbations generated through query-based gradient estimation or substitute models, sharply reducing the win rate and team reward of a QMIX-trained team with fewer perturbation steps.

## Problem & Motivation
Cooperative MARL (c-MARL) policies are vulnerable to adversarial attacks on agents' observations, which can break learned cooperation and cause large damage to the team, so robustness must be tested carefully. The authors argue that existing MARL robustness-testing methods ignore realistic implementation conditions: they often rely on MARL algorithms or differential evolution to choose victims and timing (requiring much prior knowledge, pre-training, or heavy real-time computation), require access to all agents' observations, or assume the adversary can change agents' actions directly or needs model parameters (white-box). These assumptions are hard to satisfy in reality. The work aims to bridge the gap between methodological rigor and practical implementability by being destructive yet stealthy (few perturbation steps) and operating under realistic, partial-observation, black-box conditions.

## Robustness Setting
- **Threat model / uncertainty set**: The adversary perturbs the observation of a single chosen victim agent. It does not have all agents' observations at the start and should not have much prior knowledge of the agent model; it gains information gradually through the partial observation of either one ally agent (AOA) or one enemy unit (EOA). The attack is black-box (no model parameters/gradients): perturbations are generated by querying the victim model to estimate the Q-value gradient, or via a substitute model using transferability. Attacks are sparse (launched only at screened time steps when other agents are observed) to minimize perturbation steps.
- **Setting**: cooperative MARL (agent team vs. script-controlled enemies); CTDE training (QMIX target); evaluated online during execution; black-box.

## Method
- **Two-step framework**: (1) select a victim agent and screen the attack time; (2) generate adversarial perturbations and add them to the victim's observation. Goals: minimize number of attacks, maximize team-reward reduction, and stay close to realistic conditions.
- **Ally Observation Attack (AOA)**: from the partial observation o_t of one ally agent_t, obtain the set of other agents appearing in o_t; for each, compute ΔQ_i = Q_i − Q'_i (Q-value of the chosen action before vs. after a trial perturbation); select the agent with argmax(ΔQ_i) as victim. Attack only fires when other agents are observed by agent_t (and stops when none are observed or agent_t is destroyed), so the attack time is decided by the agent itself, making it sparse.
- **Enemy Observation Attack (EOA)**: when the adversary cannot obtain any ally observations initially, it uses a single enemy's partial observation o_e; agents appearing in o_e are scored by ΔQ_i and the largest is chosen as victim. More realistic but harder; no attack is launched when no agent appears in the enemy's observation or the enemy is destroyed.
- **Query-based black-box perturbation**: use FGSM form d_perturbation(X) = ε × sgn(∇_X Q_k), where Q_k is the (maximum) Q-value of the action chosen by the agent. Since model gradients are unavailable in black-box settings, the gradient ∇_X Q_k is estimated by zeroth-order finite differences (ΔQ_k/Δx_i per input feature) obtained by perturbing each input feature.
- **Substitute-model perturbation**: to avoid repeatedly querying the victim model (which could attract attention), exploit that agents in the same team trained under the same MARL algorithm react similarly to the same perturbations; feed a target agent's observation into a pre-prepared agent model (e.g., agent0), generate perturbations from its output, and add them back to the target agent's observation (transferability attack), avoiding querying different agents.

## Theoretical Contributions
None / mostly empirical.

## Experiments
- **Environment/Benchmark**: StarCraft II Multi-Agent Challenge (SMAC); two maps: 2s3z (2 Stalkers + 3 Zealots; simpler) and MMM (1 Medivac, 2 Marauders, 7 Marines; more complex). 100 independent games per experiment, averaged.
- **Baselines**: Ablation comparisons rather than external baselines: "ALL" (adversary has all agents' observations the whole game and always attacks the max-ΔQ agent) to test the first step; "RAND" (randomly select a victim from the observed set) to test the second step; "sAOA" (substitute-model variant of AOA) for perturbation generation. QMIX-trained team without attack serves as the clean reference.
- **Evaluation metrics**: win rate (WR), death number of enemies (DE), death number of allies (DA), team reward (TR), and perturbation steps (PS, stealthiness); curves over perturbation size ε.

## Key Results
- Clean QMIX team: WR 100% / TR ~19.9 on 2s3z and WR 99% / TR ~19.4 on MMM. AOA (attacking only one agent per step) reduces WR from 100% to 4% on 2s3z and from 99% to 0% on MMM, and TR from ~20 to ~11.6 (2s3z) and ~6.1 (MMM); AOA performs even better as the environment becomes more complex (higher dimensions, more vulnerable).
- Ablation (ε = 0.3): AOA needs far fewer perturbation steps than "ALL" (about 65% on 2s3z and 21% on MMM) while maintaining the WR/TR reduction, and uses only partial (single-agent) observations versus all agents' observations. There is a performance gap between "RAND" and AOA, so randomly selecting a victim trades performance for the feasibility of skipping model queries.
- EOA performs even better than AOA on 2s3z but worse on the more complex MMM, because it only attacks when agents are observed by a particular enemy, reducing fault tolerance. The substitute-model variant sAOA performs similarly to the query-based method (almost identical on MMM) but less well on the simpler environment, suggesting agents are more similar (more transferable) in higher-dimensional, more-agent environments.

## Limitations & Future Work
- EOA's effectiveness drops in complex environments because attacks fire only when agents are observed by a specific enemy, badly reducing fault tolerance.
- The substitute-model approach underperforms in simpler/low-dimensional environments where agents are less similar.
- Only QMIX is used as the target MARL algorithm, and only two SMAC maps are evaluated; broader algorithms/benchmarks are not tested. (Explicit future-work directions are not specified in the text.)

## Relevance to Survey
A robustness-testing / adversarial-attack contribution on the observation-perturbation line for cooperative MARL. It is distinguished by emphasizing realistic, practical threat models: strict partial observation, black-box access (query-based zeroth-order gradient estimation and substitute-model transferability), and sparse low-step attacks. It connects the c-MARL adversarial-attack literature (sparse attacks, critical/victim-agent selection, state perturbations on critical agents) with single-agent adversarial-RL attack methods (FGSM, PGD, ZOO, AutoZOOM, boundary/transferability attacks), and is relevant to the survey's themes of adversarial robustness, observation/state attacks, and evaluation of robustness in MARL.

## Related Work (verbatim excerpts from the paper)
> _[Section I, Introduction]_

"There exists many techniques for testing robustness of reinforcement learning algorithms [4], [5], but only a few of them discuss about multi-agent environments. According to the victims of the attacking methods, the robustness testing methods for MARL could be classified into two types. The first kind of methods attack one determined agent in the team [6]. Attacking one determined agent could achieve good performance when the environment is simple, but it could face bottleneck when environments become more complex. Therefore, the second kind of methods, which attack multiple agents or change the attacking victims over time, is the key to test robustness [7]–[9]. However, there are still some problems need to be solved in existing methods:
• The adversary often uses MARL algorithms or differential evolution to select the victim agent and the attack time, which requires much prior knowledge about the agent team, training before the attack, or doing real-time computation during attacks. Due to these reasons, the adversary need to retrain or recompute when the environments get changed, and the immediacy of the method is also under trial.
• Carrying out existing methods often requires the access to all agents' observations, which is not always realistic in real implementation. There is an urgent need for the enhancement of practicality of testing methods.
• Some methods assume the adversary can change the actions of agents instead of using adversarial attacks to perturb the observations. The other methods using adversarial attacks need the parameters of the model. Both are often hard to implement in reality."

> _[Section II-B, Adversarial Attacks]_

"Adversarial example aims at adding small perturbations to the model inputs to lead the model give wrong classifications to the inputs at a high confidence. It was first defined by [19]. Adversarial attacks could be divided into two types: the white box attack and the black-box attack.
In the white box attack, the adversary needs sufficient access to the model parameters and gradients to launch an attack. Fast Gradient Sign Method (FGSM) [20] is a classical white box attack, which uses the gradients of loss functions on the inputs to quickly generate adversarial perturbations. Besides FGSM, Project Gradient Descent (PGD) [21] and the Basic Iterative Method (BIM) [22] also use the gradients to launch attacks. C&W [23] is another white box attack which generates adversarial examples based on optimization, while DeepFool [24] is a boundary based attack. In the black-box attack, an adversary does not need to know about the model structures or gradients, attack could be implemented by querying the model or using the transferability of adversarial examples. Query-based methods could generate adversarial examples by estimating the gradients such as ZOO [25] and AutoZOOM [26], or find the decision boundary of the model such as the Boundary Attack [27]. Methods such as [28] consider about improving the transferability of adversarial examples generated by local surrogate models."

> _[Section II-C, Robustness Testing Methods for MARL]_

"While numerous studies have explored robustness testing for single-agent reinforcement learning [4], [5], [31], fewer have addressed the multi-agent setting. Early work which applied adversarial attacks on MARL algorithms to test robustness such as [6] only attack one determined agent in the team, which might be limited in performance when environments become more complex. Other work likes [33], [34] which attacks on multiple determined agents need retrain the adversary when victims changed.
Recently, some work such as [8], [9], [40] use a MARL algorithm or differential evolution to select victim agents from the team, and the victims could be multiple and changed by time steps. Those techniques could better test the MARL algorithm for they could cause huge damage to the team. However their methods for selecting victims and corresponding actions would harm the immediacy of implementation. There are some methods such as [7], [35] use adversarial examples to attack the state of agents with no specific target. However, the appropriate limitations of using agents' observations as well as the difficulties of launching such a white box attack have not been carefully considered yet. Generally, the adversary does not have the observations of all agents in the beginning and should not have too much information of the agent model before game. Testing methods should be more realistic in the implementation conditions to reasonably improve the MARL algorithms. Therefore, we try to present a black-box testing method with realistic conditions in this paper."
