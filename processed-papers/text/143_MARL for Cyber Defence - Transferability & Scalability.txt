ABSTRACT
Reinforcement learning (RL) has shown to be effective for simple automated cyber defence (ACD) type tasks. However, there are 
limitations to these approaches that prevent them from being deployed onto real-­world hardware. Trained RL policies will often 
have limited transferability across even small changes to the environment setup. Instability during training can prevent optimal 
learning, a problem that only increases as the environment scales and grows in complexity. This work looks at addressing these 
limitations with a zero-­shot transfer approach based on multi-­agent RL. This is achieved by partitioning the task into smaller 
network machine subtasks, where agents learn the solution to the local problem. These local agents are independent of the net-
work scale and can therefore be transferred to larger networks by mapping the agents to machines in the new network. Initial 
experiments show that this transfer method is effective for direct application to a number of ACD tasks. It is also shown that its 
performance is robust to changes in network activity, attack scenario and reduces the effects of network scale on performance.
1   |   Introduction
The move to online platforms for government and commercial 
systems has allowed for huge advances in terms of efficiency 
and functionality. Unfortunately, this increasingly intercon-
nected setup means that systems have greater exposure to cyber 
threats. Malicious actors have taken advantage of this, with 
the complexity and volume of cyber attacks growing in recent 
years [1]. To counteract this threat, autonomous cyber defence 
(ACD) research looks to detect, mitigate and respond to cyber 
attacks in a faster more adaptable way using machine learning 
(ML) tools.
Reinforcement learning (RL), is one such ML method of interest. 
RL is able to learn control tasks for simple games/simulations 
beyond the level of human performance. Applications to ACD 
type tasks have shown it to be an effective method for coordinat-
ing network defence [2–4]. Previous work has demonstrated RL 
agents' ability to learn flexible defensive strategies against net-
work attacks in several simulated settings [5, 6]. However, there 
are a number of limitations to these RL approaches that prevent 
them from being deployed onto real-­world hardware. Training 
new RL policies is sample inefficient, requiring a large number 
of interactions with the task environment to explore and learn 
the underlying task dynamics [7, 8]. These trained policies will 
often have limited transferability, such that even minor changes 
to the environment setup require the policy to be retrained from 
scratch [9]. Furthermore, as the environment scales so does the 
complexity and size of the action and observation spaces [10]. 
This scaling presents a challenge to single-­agent setups, where 
increasingly longer training times are required, with agents 
often failing to fully optimise or suffering from a lack of stability 
whilst training [11].
This work looks to address these limitations, specifically for 
the ACD problem space, with a zero-­shot transfer method

based on multi-­agent reinforcement learning (MARL). This 
approach is designed to be capable of defending a varied set 
of networks across action/observation space scales, without

Transfer learning for RL aims to improve the efficiency with 
which RL policies can be adapted to new tasks. Transfer is 
achieved by the application of knowledge learned in one task do-
main to new unseen tasks [12]. There are a number of different 
approaches for encoding or applying previously learned knowl-
edge such as task mapping [13], reward shaping [14], represen-
tation learning [15] or policy transfer [16]. However, these still 
have hard limitations. They are generally confined to transfer-
ence between tasks in an environment with a fixed action state 
space. In the ACD space this means the scale of the simulated 
network must be consistent across tasks.
MARL trains multiple agents simultaneously within the same 
environment instance. It can potentially address the scaling 
challenges presented by enterprise systems where the net-
work environments are highly complex [17]. A combination of 
MARL, multi-­task and transfer learning paradigms has been 
proposed as the basis for a fully task-­agnostic learning process 
[18, 19]. MARL agents have also demonstrated learning effec-
tive cyber defence strategies [20–22]. Despite this, MARL has 
been highlighted as an underdeveloped area in RL for ACD re-
search [17].
The transfer approach presented here involves training a 
MARL setup on a small-­scale network where agents can more 
easily achieve optimal performance. The network state space 
is partitioned into smaller subtasks, providing each agent with 
the information of only a single machine in an ACD network. 
Centralised Training with Decentralised Execution (CTDE) 
MARL approaches is used to encourage agents to act collabora-
tively. These agents are then remapped to novel network setups 
at inference.
This work shows MARL-­based transfer to be highly effective, 
outperforming the reward values achieved by baseline agents. 
Performance is also shown to be less susceptible to the scale 
of the problem space and robust to changing network activity. 
Further work looks into how the agents can be generalised with 
abstracted, standardised observation spaces.
This work has required the development of a variation of 
DSTL's PrimAITE [23] environment capable of supporting 
multi-­agent algorithm learning. Expanding the environment 
such that multiple machine-­level operations can be performed 
simultaneously.
To summarise, there are three main contributions from this 
work. An environment, MARL PrimAITE, an extended ver-
sion PrimAITE with partitioned networks to enable MARL 
compatibility. A comparative study assessing the performance 
between single-­agent Proximal Policy Optimisation (PPO) 
and CTDE MARL algorithms for ACD. A demonstration 
of scale invariant zero-­shot policy transfer, using a MARL 
setup consisting of network-­invariant local agents and pooled 
observation.

2.1   |   MARL
Single-­agent RL tasks are formulated as a Markov decision 
process (MDP) = (, , , , 훾), where  is the set of states, 
 is the set of network actions,  are the rewards,  the state 
transition probabilities and 훾 is the discount factor. The agent 
learns a policy 휋: → to solve the MDP by maximising 
the expected reward of an episode. MARL methods use mul-
tiple agents, trained simultaneously, acting either compet-
itively or cooperatively in the same environment instance. 
Cooperative MARL tasks can be represented as a partially 
observable MDP (POMDP), = (, , , , , 훾) [24], where 
= {1, 2, … , N} and i is the set of actions for agent i. 
The partial observability is due to the fact that agents have a 
localised view of the state space. The set of agent's observa-
tions is given by = {1, 2, … , N} and i is the observa-
tion of agent i.
Three MARL algorithms were used in this work: Independent 
Proximal Policy Optimisation (IPPO), Multi-­Agent Proximal 
Policy Optimisation (MAPPO) and Heterogeneous-­Agent 
Proximal Policy Optimisation (HAPPO). These are all derived 
from the single-­agent PPO algorithm [25].
PPO is widely used for its balance of stability, performance and 
relative simplicity. It is a policy gradient, actor-­critic approach 
containing two distinct networks: the actor which determines 
the action taken and the critic network which provides a quality 
metric of the action. What distinguishes PPO from other actor-­
critic methods is the use of probability ratio clipping to restrict 
the scale of the update to the policy.
The ratio clipping function retains the last policy used to sample 
from the environment 휋휃old in addition to the current sampling 
policy 휋휃, giving a measure of difference between the two. The 
PPO loss function (Equation  2) is a combination of this ratio 
with the estimated advantage A휋. A clipping function restricts 
the ratio to some small interval, ensuring stability by bounding 
the scale of the update to the policy.

2.1.2   |   MAPPO
The key distinguishing feature of MAPPO is the shared critic 
model, with parameters shared across all the agents [28]. The 
critic takes in the set of all agents' observations as inputs to the 
value function (Figure 1). Via the critic, individual agents learn 
using feedback from the global context of the problem, encour-
aging cooperative behaviours.
At inference time the agents only use the actor component, dis-
carding the shared critic. As the critic has a global view of the 
game state, this CTDE approach reduces the stability issues of a 
fully independent multi-­agent setup.
2.1.3   |   HAPPO
A limitation of the shared critic approach is that the critic acts as 
a multi-­task model. In RL these can often have unstable or sub-­
optimal learning as agents can have conflicting policy update 
steps. HAPPO [29] uses a sequential update process to address 
the sub-­optimality. HAPPO also makes use of a shared critic to 
encourage cooperative behaviours. At training time, the policies 
update sequentially rather than in parallel. In the policy loss 
function, updates to the actors are made with respect to the pre-
vious agent's advantage function, shown in Figure 1. This loss 
ensures monotonic updates of the policy, improving learning 
stability.
2.2   |   Spatial Pyramidal Pooling (SPP)
A SPP layer is typically used with convolutional neural networks 
to standardise indeterminate size arrays into a fixed-­length 
representation [30]. The original input is divided into a fixed 
number of overlapping windows, maximally pooling each, then 
concatenating them into a vector. Multiple passes are run, with 
a range of window scales to capture information on features at 
different scales, reducing loss of spatial details. In RL tasks SPP 
layers have been used to produce a standardised vector repre-
sentation on the variable scale visual observation spaces [30]. 
This has been effectively demonstrated on the state space of 
real-­time strategy games [30].
2.3   |   Transfer RL
Transfer in an RL setting is defined as the attempt to learn 
an optimal policy for some novel MDP scenario new by 
­utilising learned knowledge encoded in policies trained on 
an initial set of scenarios 
{i}
. Zero-­shot transfer for RL is 
a training process which produces sufficiently generalised 
­policies such that the policies can be used to solve novel 
MDP tasks {new} without the need for further training upon 
deployment.
The set of tasks for zero-­shot RL transfer can be formulated as 
a Contextual-­MDP (CMDP), = (, , , , , 훾, , p(c)) [31], 
where  is the context space, the set of task parametrisations, 
and p(c) is the context distribution. The CMDP extends POMDPs 
to encompass a task distribution. Any particular context setup is 
itself a POMDP [31].

3   |   MARL Transfer Approach
As previously discussed, the aim of this work is to demonstrate 
how a MARL formulation of ACD tasks can be used for zero-­
shot transfer. Furthermore, this work aims to demonstrate that 
the MARL setup can allow for the transfer of learned knowledge 
across network scales and therefore across different action and 
state spaces.
The proposed MARL setup breaks the network defence 
task into its constituent subtasks, specifically dividing the 
global task into a series of machine (node) level management 
POMDPs. Agents are trained to handle each node level task 
on a set of simple network setups. The action and observation 
spaces of these ‘local’ node level agents consist of only node 
level actions and the properties relevant to the node. These 
spaces are therefore independent of the scale of the overall 
network.
Once trained these ‘local agents’ can control nodes in novel 
ACD task setups by mapping them to nodes in the new network, 
as shown in Figure 2. As they are already optimised to solve 
the node control task no additional training is required. Agent 
mappings are determined by the similarities between the local 
agents' original training node setup and the new network node 
setup. Mappings are a one-­to-­many relationship with the poten-
tial for duplicates of a local agent being used to control multiple 
nodes in a new task.

Two versions of the observation space were produced. The first 
used a padded observation space to be able to accommodate up 
to M links. Local agents using this observation space are de-
scribed as ‘padded’. However, padding the observations still en-
forced an upper limit on the potential scale of the environment. 
The second version used a one-­dimensional SPP layer to reduce 
the variable length links component to a fixed length vector. 
This representation can theoretically handle any number of link 
properties, and agents trained using SPP link representations in 
observation space are described as ‘pooled’ (Algorithm 1).
4   |   PrimAITE
The proposed transfer method is trained and tested using a vari-
ant of the PrimAITE network simulation environment, developed 
for the Autonomous Resilient Cyber Defence (ARCD) programme 
[23]. The environment models the network as a graph of nodes, 
where the nodes represent endpoints, servers and switches. Each 
node has its own hardware and software state. The edges of the 
graph represent links between the network machines; these simu-
late the transfer of data. Traffic flow along these links can be mod-
erated by transfer protocols and firewalls.
The AI agent is responsible for defence of the network through 
machine level operations such as repairing nodes and con-
trolling the firewalls. Green (legitimate user) activity and red 
(malicious) activity are modelled by a mixture of machine level 
operations and Information Exchange Requirements (IERs). 
IERs are used to initiate traffic loading on the network.
The AI blue agent gets rewards throughout the attack scenario 
based on the health of the network and the IERs which are 
successful. At each timestep, the current status of each node is 
compared against a reference environment and a reward is given 
based on the change in state. The environment also returns a 
negative reward for any successful red IERs or any unsuccessful 
green IERs. These rewards in combination provide a summary 
of the health and usability of the network. An agent achieving 
an optimal scenario would return an episode reward of 0.
4.1   |   MA-­PrimAITE
PrimAITE is only compatible with single-­agent algorithms. To 
train MARL algorithms, its capability has been extended to han-
dle multiple agents working simultaneously across the network. 
This augmented environment is denoted as MA-­PrimAITE [32].
In comparison to the standard PrimAITE rollout, where at each 
timestep the environment accepts one defensive action, MA-­
PrimAITE accepts a collection of actions per timestep. These are 
simultaneously applied to the network to establish the next state.
The global observation space is mapped to a set of node-­level 
equivalents. These local agent observations for MA-­PrimAITE 
consist of the properties of a node and its associated links. The 
nodes have four key properties:
•	 Hardware status
•	 Operating system status
•	 File system status
•	 A status for each service on the node
Each link observation also has the following properties:
•	 Traffic volume as a percentage of bandwidth
•	 Associated traffic level for each service
•	 Hardware status (always set to null value of 0)
•	 File system status (always set to null value of 0)

5   |   Experimental Setup
To test MARL zero-­shot transfer a set of three MA-­PrimAITE 
networks – small, medium and large – were produced (Figure 3). 
These are examples of networks across three different scales 
consisting of 6, 15 and 30 nodes respectively.
The small network is a simple six-­node network based on a basic 
DDOS attack. There is minimal green activity represented by 
one IER and a simple red attack where the red agent attempts to 
compromise two nodes in sequence.
The medium and large networks are extensions of this small 
network. The proportion of node types and connectivity of 
nodes varies slightly in each case. The setups used in the initial 
experiments retain the small networks' pattern of red and green 
agent activity.
The local agents used for transfer testing were trained on the 
small network, then mapped to both the medium and large 
networks. Typically MARL setups are more unstable and un-
predictable to train than single-­agent systems [20]; training the 
agents in the simple small network reduced the complexity and 
computational cost of the problem. This allowed the agents to 
be rigorously tuned to optimise performance on the sub-­tasks.
5.1   |   Training Setup and Assessment Metrics
Each network scenario used an episode length of 256 timesteps. 
The natively trained agents were each trained for between 500 and 
1000 episodes depending on the network scale. Local agents for 
transfer and the single-­agent baselines were trained on the small 
network for a total of 150,000 timesteps covering 585 episodes.
Sets of local agents using both observation variants were trained. 
The padded observation was configured to support up to eight 
links on a node. Unpopulated links had all properties set to zero. 
The pooled observation used a SPP layer with windows pooling 
the link information into 6, 4 and 2 components. Therefore, the 
final link representation was a length 12 vector.
The efficacy of each setup is measured using the average reward 
per episode. As stated in Section 4, the closer the reward is to 
zero the more effective the agent was at mitigating threats to 
the network. To get a representative sample of the performance, 
the results are given as the mean of the average reward across 
50 episodes.
For the natively trained agents a sample of 50 episodes was taken 
from a post-­training run on the task. It should be noted that as 
MA-­PrimAITEs' reward is linked to the properties of the nodes, 
the potential for negative rewards increases with the scale of the 
network.
5.2   |   Baseline Comparators
The difference between the expected reward returned for the 
context sets Train and Test can be used to understand the gen-
eralisation of the agents. However, this measure is highly de-
pendent on the environment and reward setup [31]. This work 
instead follows the recommendations of [31] and uses problem-­
specific baselines to gauge zero-­shot transfer effectiveness.
Two methods are used to provide a baseline to the MARL trans-
fer approach; these were a multi-­action single-­agent PPO policy 
agent and a set of MARL agents. Both baseline methods were 
trained directly on the test network (natively trained).
The natively trained MARL agents are a set of local node-­level 
agents trained directly on the medium and large network tasks. 
These agents provide a measure of the performance of the 
MARL setup for the specific test task, giving a like-­for-­like com-
parison to the performance of the transferred agents.

agent that acts on a single node per timestep. An adapted ver-
sion (PPO multi-­action) was produced where each action in the 
agents' action space corresponded to a distinct combination of

6   |   Results
6.1   |   Small Network Training
The training results of the IPPO, MAPPO and HAPPO agents 
[32] on the small network are shown in Figure 4. The MARL 
agents were trained using the padded variant of the local obser-
vation space. More details on the training and hyperparameter 
tuning of the local agents are in Appendix A.
MAPPO achieved the best performance of the MARL meth-
ods, approximately matching the average episode reward of the 
single-­action PPO agent, albeit with greater training instability. 
The final trained reward of both HAPPO and IPPO fell short of 
MAPPO, though HAPPO displayed more stable training prog-
ress than the other MARL methods.
The multi-­action PPO baseline showed little to no ability to 
learn effectively. This result is due to the action space being too 
large for the policy network to fully explore the effects of actions 
on the environment. As such PPO multi-­action results are pre-
sented for the small network only.
MAPPO agents were also trained using the pooled observation 
space. The training performance is shown in Figure  5. The 
pooled agents' performance across the training was considerably 
less stable than the padded MAPPO and the single-­agent PPO. 
The pooled agents were able to train to a performance plateau 
with additional training episodes. Whilst the performance of the 
pooled agents approached that of padded MAPPO and PPO it 
was not able to consistently match their average episode reward.
6.2   |   Transfer Performance
The local agents trained on the small network were mapped to 
nodes in the medium and large networks. The agent mappings 
were based on the similarity to the training setup, determined 
by the node type and number of links. The local agents were 
deployed on the nodes at test time based on this mapping.
These experiments are classified as an IID zero-­shot test. Whilst 
the overall task was significantly different due to the change in 
problem space scale, the dynamics of the node-­level task are un-
changed and therefore within the context distribution of the train-
ing. The results of the transfer experiments are shown in Table 1.
The results for the transferred agents showed a significant im-
provement in reward performance over the natively trained 
equivalent. For the Transfer padded agents, on the medium 
network, the average episode reward is 39% lower than the 
native agents and 64% lower for the large network. The in-
crease in the average reward is even more pronounced for the 
Transfer Pooled agents, with an improvement of 56% for the 
medium network and 78% for the large network. These results 
clearly demonstrate that agent experience can be effectively 
transferred across network scales.
The pooled agents consistently outperformed the padded agents; 
this demonstrates the additional benefit that abstracting the 
observation can have on transferability. However, the pooled 
agents also showed greater variability in episode performance. 
When considering the distribution of average episode rewards 
(Figure  6), the pooled transfer agents had a significantly 
wider distribution of results than the padded transfer agents.

7   |   Further Work
Whilst this work has shown effective cross-­task, cross-­
observation scale transfer, there are still limitations to this 
approach. These include the number of unnecessary actions that 
come from agents acting on the environment in parallel and the 
dependence on an effective agent-­to-­node mapping for good re-
ward performance.
Reducing the capability for local agents to act unnecessar-
ily could further improve the network defence performance. 
Additional local network context, could be used to reduce the 
number of cases where agents may act negatively. Action mask-
ing could similarly be used, restricting the number of actions an

The node mapping process could be refined by learning auto-
mated optimal mappings. The paper [30] used grid-­wise con-
trol as a way to assign an arbitrary number of MARL agents to 
tasks. This used an encoder-­decoder approach to learn a spa-
tial representation of the observation space, partitioned into a 
grid. Agents' actions are then assigned to environment inputs 
according to the grid. This learned approach to assigning agents' 
actions to task components could reduce the performance de-
pendency on effective agent mapping.
Additionally, there are a number of methodologies that could 
be used to extend the approach shown here to further improve 
performance. Hierarchical approaches could be applied to fur-
ther partition the problem space into distinct detection, rec-
ommendation and action-­type agents. This could abstract the 
local agent tasks away from the global ACD task, improving the 
transfer and generalisation performance. Hierarchical setups 
could also be used to moderate the actions of individual agents 
through the use of a manager agent.
The application of the SPP layer to the observations as a sim-
ple generalisation method gave a significant boost to the over-
all performance. Learned observation representations have 
been shown to aid generalisation for tasks across observation 
space types [33]. Furthermore, learning a representation that 
conforms to bisimulation metrics removed task irrelevant noise 
from the observation [34]. These could be the basis of improved 
methods to standardise the observation space for local agents.
Finally, whilst PrimAITE represents a high-­fidelity simulated 
environment, it is still abstracted away from the real-­world net-
work defence task. Applying the MARL transfer approach to an 
emulated network, such as Imaginary YAK, would provide a 
more realistic test of the local agents' adaptability in real-­world 
settings.
8   |   Conclusion
The results in this paper have demonstrated that MARL agents 
can be effectively trained in complex ACD environments. The 
small network training results showed that MARL solutions 
can solve the network defence task using complex multi-­actions 
to the same level of performance as a single-­action PPO agent. 
The fact that MAPPO agents could achieve this result where 
IPPO agents could not showed the advantages of CTDE ap-
proaches in this setting. The multi-­action PPO agents' inability 
to learn on an equivalent action space has also demonstrated 
the advantages of a MARL approach to distributed control 
problems.
The key result of this paper is that the proposed MARL transfer 
method is capable of effective zero-­shot transfer across envi-
ronment observation spaces. It was shown to be highly effec-
tive in the MA-­PrimAITE ACD setting, able to not only match, 
but significantly outperform the levels of reward achieved by 
the equivalent MARL setup trained directly on the task. This 
result held across network scales, attack patterns and levels of 
network activity. It was shown to be robust to a range of tasks 
significantly different from the original training scenario.
The performance of this transfer method also scales effectively 
with the task problem space. The difference in overall reward 
between the medium and large networks was significantly im-
proved for the transferred agents than for those natively trained 
on the task.
Using SPP layers to standardise the observation space has 
proved to be of benefit to the transfer approach. This abstracted 
observation achieved an increase in reward values and further 
reduced the difference between the performance across network 
scales. Further work could focus on this area, investigating ad-
ditional methods in representation theory that can standardise 
and generalise the agents' setting.

Appendix A
Hyperparameter Tuning for Initial Experiments
To ensure that the algorithms tested were achieving optimal performance on the MA-­PrimAITE environment, a hyperparameter sweep was per-
formed on each of the main algorithms tested (HAPPO, MAPPO, IPPO). For each algorithm a random search was performed with a set range of 
values to test for each hyperparameter; each search was performed for 200 episodes at 10,000 timesteps per trial.
Once this initial search was completed the impact of each hyperparameter on mean episode reward was measured and a further, longer search was 
conducted with a refined range of hyperparameter values (500 episodes, 30,000 timesteps per trial).
For each of the tested algorithms (MAPPO, HAPPO and IPPO) a random search sweep was implemented on the clip parameter, entropy coefficient, 
gamma, lambda, learning rate and value function loss coefficient. The hyperparameters that had the largest impact on performance were learning 
rate and lambda (Figure A1). For the range of the values tested, changes in these affected training performance to a greater effect than the others 
tested for all three algorithms.
In all cases the MARL algorithms are highly sensitive to the hyperparameter setup; this tallies with the findings of previous work on MARL for 
ACD [20]. There is the possibility that further performance improvements may be achievable. However, it is difficult, as each task and algorithm 
combination appears uniquely sensitive to different factors.

The initial experiments used a semi-­random mapping to assign the pre-­trained agents to the new scenario network nodes. Agents were assigned to

Each mapping has been run for 10 episodes to provide a sample of the performance distribution. Whilst the results, shown in Figure B1, demonstrate 
some variance in the average reward performance, in most cases this is restricted to within 0.0005 reward. The distribution of rewards across the

pings provide the best performance. This is likely due to these agents training across a more varied set of link observations.

Appendix C
Few-­Shot Training Experiments
Few-­shot training experiments were run to establish if further performance gains are possible by continuing training on the target task. The actor 
policy can be mapped and trained in the new task setting without any further amendments. However, the MAPPO critic cannot be mapped in the 
same way, since the shared critic acts across all agents requiring a global observation. Two approaches are used to account for this. The first, trained 
critic, uses the existing critic with a reshaped first layer. The weights of this layer are mapped from the weights corresponding to the original agent 
mapped to the node. The second approach, untrained critic, uses a newly initialised critic model with untrained weights.
MAPPO few-­shot experiments were run for both test scenarios, with agents trained for up to 300 episodes, shown in Figure C1. In both cases the 
few-­shot performance was either lower or matching the zero-­shot case. A range of learning rates has been tested; however, larger learning rates lead 
to catastrophic forgetting and a significant dip in overall reward. The results suggest that using a trained critic provides better overall performance, 
in particular for the medium network where the reward difference is sizable. Whilst further refinement may be able to show few-­shot improvement, 
given the results of the initial experiments this work has focused on the zero-­shot transfer case.
